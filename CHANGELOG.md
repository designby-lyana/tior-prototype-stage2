## 2026-08-10

- **Кошик — аудит проти дизайн-системи, qty-степер (кольори/рамка/радіус):** базовий `.qty-stepper` (застосовується скрізь, крім product-card v2 на Search, де лишається ізольований `--radius-xs-v2`) мав фон/рамку `var(--bg-chip)` — суцільна бежева заливка з рамкою того самого кольору (фактично невидима) — замість білого фону + видимої рамки; `border-radius` був хардкоджений 4px замість `--radius-lg` (8px, канон DS §4). Виправлено на рівні базового класу — торкнулось усіх інстансів степера сайту (Кошик, "Powtórz zamówienie z historii", Search тощо), не лише Кошика. Кнопки `.qty-btn` тепер прозорі (не залиті суцільним кольором), стани приведені до референсних скрінів DS: hover → `var(--border-subtle)` (**новий токен** `#EDEBE9`), active/pressed → прозорий фон + іконка `var(--accent-primary)` (було суцільна заливка `--accent-pressed` + білий текст), focus-visible → `box-shadow:var(--focus-ring-inset)` (**новий токен**, inset-кільце — свідомий вибір, бо батьківський контейнер має `overflow:hidden` і зовнішній `--focus-ring` обрізався б). Commits `fa14377`, `f7261e0`.
- **Кошик — typography qty-степера:** `.qty-value` мав `font-weight:400` у коді, хоча в DS-доці вже задокументовано 18px/700 (§9.3) — приведено у відповідність код↔док. `.qty-btn` (`−`/`+`) не мав явного `font-family` і рендерився дефолтним Arial браузера замість Outfit — додано `font-family:var(--font-body)` + `font-weight:700` (**нове рішення**, раніше не задокументоване — для однакової жирності символів з цифрою), обнулено UA-padding кнопки (браузерний дефолт `1px 6px` заважав центруванню). Commit `a53fa59`.
- **Кошик — висота степера, навмисний виняток:** висота степера в рядках картки товару кошика (щільний список) = 32px замість канонічних 40px — підтверджено як свідоме рішення саме для цього контексту, не баг верстки. Потребує запису в DS-доці як documented exception (за аналогією з CTA-кнопкою 12px радіуса). Commit `f7261e0`.
- **Кошик — вирівнювання степера в рядку:** новий layout-патерн, раніше не задокументований — коли степер стоїть в одному ряду з багаторядковим контентом (ціна за шт. + сума), контейнер (`.cart-item-bottom`) вирівнюється `align-items:flex-end` (по нижній лінії контенту), а не по центру. Commit `f7261e0`.
- **Кошик — gap кнопок footer (Primary+Secondary):** `.cart-summary-actions` мав хардкод `gap:16px`; звірено з канонічним референсом — тим самим стеком кнопок у попапі "Dodano do koszyka" (`.atc-drawer`, `gap:8px`) — приведено до `var(--space-sm)`. **Новий патерн** (раніше не задокументований): вертикальний стек Primary+Secondary кнопок = gap 8px, не 16px. Commit `2a28dda`.
- **Кошик — мінімальний розмір шрифту (§6):** `.cart-item-size` (типорозмір шини) і `.cart-item-unit` (ціна за шт.) були 13px/14px — порушення задокументованого мінімуму 16px (виняток лише для лейблів модальних форм, 12px). Приведено до 16px. Commit `953f4ed`.

- **Fix:** картка №2 (дублікат) з'являлась одразу при вході на екран результатів, хоча мала бути прихована до кліку. Причина: приховування було на inline `style="display:none"`, а `runResultsSearch()` (запускається автоматично при кожному вході на screenResults через `resetResultsPagination()`) явно скидає `style.display=''` для ВСІХ `.product-row` — це й "розкривало" картку №2 без кліку. Також id="refCardTwin" не працював як довгостроковий якір — пагінація (`buildResultsCard`) клонує картки з пулу і зрізає `id` з кожного клону. Виправлено: видимість тепер керується класом `.ref-card-twin` / `.is-revealed` (CSS, `!important`) замість inline style, а JS шукає картку №2 як `.nextElementSibling` клікнутої картки №1 (із запасним варіантом через `.querySelector`) замість `getElementById`. Лічильник "N produktów" (`updateFilterState`) також оновлено, щоб не рахувати приховану картку №2. Перевірено симуляцією кліків + повторного входу на екран (jsdom).
